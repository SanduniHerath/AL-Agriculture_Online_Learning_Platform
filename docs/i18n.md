# Translations (i18n)

The website is bilingual: **Sinhala (default)** and **English**. Tamil is planned.
Library: [next-intl](https://next-intl.dev).

## Where things live

| What                       | Where                                                                          |
| -------------------------- | ------------------------------------------------------------------------------ |
| UI text                    | `apps/web/messages/si.json`, `apps/web/messages/en.json`                       |
| Supported locales          | `LOCALES` in `packages/shared/src/constants.ts`                                |
| Routing (`/si`, `/en`)     | `apps/web/src/i18n/routing.ts`, `apps/web/src/proxy.ts`                        |
| Locale-aware `Link`/router | `apps/web/src/i18n/navigation.ts` (always import from here)                    |
| Prices, dates, durations   | `formatLkr`, `formatDate`, `formatTime`, `formatDuration` in `@al-agri/shared` |

Content the teacher edits (unit titles, teacher profile, testimonials, contact details) is
**not** in these files - it comes from the database in both languages (decision D14).

## Adding or changing a string

1. Add the key to **both** `en.json` and `si.json`, in the right namespace (`home`, `units`, `auth`...).
2. Use it: `const t = useTranslations("units"); t("title")` (server components may also use
   `await getTranslations(...)`). Keys are type-checked against `en.json`.
3. Run `pnpm --filter @al-agri/web test` - the tests fail if the two files have different keys,
   different placeholders, or invalid syntax.

### Placeholders and plurals (ICU syntax)

```json
"lockedPrice": "Locked · {price}"
"meta": "{subparts, plural, one {# sub-part} other {# sub-parts}} · {videos, plural, one {# video} other {# videos}}"
"acceptTerms": "I agree to the <terms>Terms</terms> and <privacy>Privacy Policy</privacy>."
```

- Pass formatted values: `t("lockedPrice", { price: formatLkr(1500, locale) })`.
- Sinhala does not need plural forms - use the plain number: `"අනු කොටස් {subparts}"`.
- Rich text tags are filled with `t.rich("auth.acceptTerms", { terms: (c) => <Link ...>{c}</Link> })`.

## How the language is chosen

1. The locale in the URL (`/si/...`, `/en/...`).
2. The `NEXT_LOCALE` cookie, set for one year when the student uses the සිං / EN switch.
3. Otherwise **Sinhala** - the browser's language setting is ignored on purpose (decision D13).

## Adding Tamil later

1. Add `"ta"` to `LOCALES` in `packages/shared/src/constants.ts`.
2. Create `apps/web/messages/ta.json` with every key (copy `en.json` and translate).
3. Add the Noto Sans Tamil font in `apps/web/src/app/fonts.ts` and a `[lang="ta"]` rule in
   `globals.css` (same as the `[lang="si"]` rules).
4. Add `ta` labels to the `language` namespace and to `LanguageSwitch`.
5. Database content gets Tamil columns/rows (the schema is designed for this in Phase 2).
